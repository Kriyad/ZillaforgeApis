productsByList Flow Service

Interface getCategorisedProducts   Stateless   Private

Purpose

This flow service retrieves a product catalog from an external REST API, validates pricing thresholds, and categorizes each product into one of three price tiers (Budget, Standard, Premium) based on its list price relative to configurable threshold values.

It is designed to be invoked as part of a product catalog integration where downstream consumers need products pre-segmented by price category for display, filtering, or business logic.

Business Rules

Threshold Validation (Pre-processing)
Before processing products, the service validates that both budgetThreshold and premiumThreshold are valid numbers and that budgetThreshold < premiumThreshold. If validation fails, the flow exits with a FAILURE signal.
Product Categorization Logic
For each product with a valid numeric listPrice:
Category Condition Mathematical Expression
Budget Price is below budget threshold listPrice < budgetThreshold
Standard Price is at or above budget threshold but below premium threshold budgetThreshold ≤ listPrice < premiumThreshold
Premium Price is at or above premium threshold listPrice ≥ premiumThreshold
Uncategorised Price is not a valid number !isNumber(listPrice)
HTTP Error Handling
If the catalog API returns any HTTP status other than 200, the flow exits with FAILURE and includes the status code in the error message.
Exception Handling
Any exception during the HTTP call, JSON parsing, or threshold validation is caught and results in a FAILURE exit with the error message.

Inputs

Parameter Type Required Description
apiUrl String Yes Full URL of the catalog REST API endpoint (e.g., https://api.example.com/v1/products).
apiKey String Yes API key sent as x-Gateway-APIKey header for authentication.
budgetThreshold String Yes Lower price boundary. Must be a valid number and less than premiumThreshold.
premiumThreshold String Yes Upper price boundary. Must be a valid number and greater than budgetThreshold.

Note: Thresholds are passed as Strings but validated as numeric values using pub.string:isNumber.

Outputs

Parameter Type Description
products recordList List of enriched product records, each containing all original fields plus a priceCategory field with value: Budget, Standard, Premium, or Uncategorised.

Processing Flow

  1. Initialize Headers — Create empty headers record with x-Gateway-APIKey field.
  2. Set API Key — Copy input apiKey into headers/x-Gateway-APIKey.
  3. Call Catalog API — pub.client:http GET request to apiUrl with headers, 30s timeout, response loaded as bytes.
  4. Check HTTP Status — If status ≠ 200, exit with FAILURE.
  5. Parse Response — Convert bytes to UTF-8 string (pub.string:bytesToString), then parse JSON to document (pub.json:jsonStringToDocument).
  6. Extract Products — Map responseDoc/output array to items list.
  7. Validate Thresholds —
    • Check both thresholds are numeric (pub.string:isNumber)
    • Verify budgetThreshold < premiumThreshold via pub.math:subtractFloats + pub.string:indexOf for sign detection
  8. Loop Through Products — For each item in items:
    • Copy item to enrichedProduct
    • Validate listPrice is numeric
    • If invalid → set priceCategory = "Uncategorised"
    • If valid → compute diffFromBudget and diffFromPremium, determine signs via indexOf for "-" character
    • Branch logic:
      • budgetSign == 0 (negative) → Budget
      • premiumSign == -1 (zero or positive) → Premium
      • Default → Standard
    • Append enrichedProduct to output products list

Dependencies

  • pub.client:http — HTTP client for REST API call
  • pub.string:bytesToString — Convert HTTP response bytes to string
  • pub.json:jsonStringToDocument — Parse JSON string to IS document
  • pub.string:isNumber — Validate numeric strings
  • pub.math:subtractFloats — Float subtraction with precision
  • pub.string:indexOf — Detect negative sign in difference results
  • pub.list:appendToDocumentList — Build output product list

Integration Notes

  • The service expects the catalog API to return a JSON structure with an output array containing product objects with the defined fields.
  • Threshold values are passed as strings to allow flexible input formats but must represent valid decimal numbers.
  • The priceCategory field is added to each product record; ensure downstream consumers expect this field.
  • Service is stateless and thread-safe — suitable for concurrent invocation.
  • No caching is enabled (cacheResults: false); each call hits the catalog API.
